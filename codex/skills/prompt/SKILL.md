# 프롬프트 개선

사용자가 준 목적을, 그 프롬프트를 실행할 Codex가 재질문 없이 정확하게 수행할 수 있는 프롬프트로 만든다.

입력: $ARGUMENTS (비어 있으면 목적이나 초안을 먼저 물어본다)

## 절차

1. **대상 파악** — 프롬프트가 이 프로젝트의 코드를 대상으로 하면, 관련 파일을 탐색해 실제 경로·구조·제약을 프롬프트에 반영한다. 다른 저장소가 대상이면 탐색하지 않는다.

2. **결정 질문** — 최종 프롬프트를 쓰기 전에, 아래 세 갈래에 해당하는 것을 모두 찾아 AskUserQuestion으로 선택지와 함께 묻는다. 관련 질문은 한 호출에 묶는다:
   - 요구의 실제 성격이 갈리는 지점 (예: "실패 시 재시도"로 충분한가, "반드시 결국 전송"이 필요한가)
   - 결과물에서 사용자 눈에 보이는 동작이 갈리는 제품 결정 (예: on/off 토글 vs 3단 선택)
   - 사용자가 제시한 방법보다 더 나은 방법이 있는 경우 — 트레이드오프와 함께 선택지로 제시하고, 사용자가 고른 쪽으로 쓴다

   수치·네이밍 같은 사소한 구현 세부는 묻지 않고 합리적 기본값으로 채운다. "기본값으로 채우고 나중에 알려주면 된다"는 판단이 들면 위 세 갈래에 해당하는지 다시 본다 — 해당하면 묻는 것이 이 스킬의 존재 이유다.

3. **프롬프트 작성** — 입력과 같은 언어로, 아래 요소를 이 순서로 담는다 (해당 없는 요소는 뺀다):
   - **목표**: 무엇이 되면 완료인지
   - **컨텍스트**: 실행 Codex가 알아야 할 배경과 파일 경로. 모르는 저장소의 세부(스택, 기존 패턴)는 실행 Codex가 먼저 탐색해 기존 패턴을 따르도록 지시
   - **요구사항**: 구체적 동작. 질문으로 확정된 결정을 반영
   - **범위**: 하지 말 것, 건드리지 말 것
   - **검증**: 완료를 확인하는 방법 (명령, 테스트, 수동 절차)

4. **저장** — 프로젝트 루트의 `docs/Prompt-{내용}.md`로 저장한다. `{내용}`은 주제 요약 (예: `Prompt-업로드재시도.md`). `docs/`가 없으면 만들고, 같은 주제를 다듬는 중이면 같은 파일을 갱신한다. 파일에는 실행 Codex에 붙여넣을 프롬프트만 담는다.

## 최종 보고

저장 후 채팅 메시지는 다음으로 구성한다:
- 저장 경로
- 기본값으로 채운 결정 목록
- 원래 입력 대비 개선·변경한 지점 요약
